# 数据库设计

本文档描述 Narra 当前代码中的持久化模型，供开发和排障时查阅。表结构、约束和索引以 [`internal/model/entity/`](../internal/model/entity/) 的 GORM 声明及 [`internal/app/app.go`](../internal/app/app.go) 的迁移清单为准。早期的 [V1 数据库设计](database-design-v1.md) 记录了当时的方案，其中“无用户表、无鉴权、无页面重试”等内容已不适用于当前实现。

## 1. 存储边界

- **PostgreSQL + pgvector** 保存账号、课堂、页面、知识库、模型配置与讨论记录。服务启动时先创建 `vector` 扩展，再执行 GORM `AutoMigrate`。
- **Redis + Asynq** 承载异步任务投递和消费，不是课堂内容的最终数据源。任务恢复依据数据库中的课程、页面状态及 checkpoint。
- 文件原件、生成音频等二进制内容存储在本地目录或配置的对象存储中，数据库保存路径与业务元数据。
- 用户模型、Embedding、重排和视觉模型的 API Key 在数据库中以密文保存；平台默认模型的密钥由环境变量注入。密码只存哈希。

多数业务表使用 `bigint` 自增主键 `id`，并带 `created_at`、`updated_at`。时间以 `timestamptz` 存储。可变的计划、页面内容、配置快照与事件负载使用 `jsonb`；字段的精确类型和约束应查实体定义。

## 2. 数据关系

```text
users
  ├─ folders ──────────────┐
  ├─ preset_agents         │
  ├─ 模型与工具配置          │
  ├─ knowledge_documents ── knowledge_chunks ── knowledge_embeddings
  │        └─ knowledge_upload_records（弱关联，文档删除后记录保留）
  └─ classrooms <──────────┘
       ├─ classroom_agents ── preset_agents
       ├─ scenes ── scene_segments
       └─ classroom_conversations
            ├─ conversation_messages
            ├─ orchestration_runs ── agent_turns
            ├─ conversation_events / context_compactions
            └─ shared_context_memories / agent_trace_spans
```

`owner_id` 是私有业务数据的归属字段。读取和写入时仍须在服务与仓储层按当前用户过滤；数据库外键只能保证归属用户存在，不能代替授权检查。

## 3. 表清单

当前启动时 `AutoMigrate` 的表按业务分组如下。表名均为实际 `TableName()` 返回值。

| 领域 | 表 | 作用 |
| --- | --- | --- |
| 账号 | `users` | 手机号、密码哈希和验证时间 |
| 课堂 | `folders`、`classrooms` | 用户文件夹、课程主记录及生成计划 |
| 课堂 | `preset_agents`、`classroom_agents` | 可选角色及课程中的角色与音色关联 |
| 课堂 | `scenes`、`scene_segments` | 课件页面、内容块与讲解段落 |
| 知识库 | `embedding_models`、`embedding_settings` | 向量模型身份及连接配置 |
| 知识库 | `knowledge_documents`、`knowledge_upload_records` | 可检索文档资产与上传历史 |
| 知识库 | `knowledge_chunks`、`knowledge_embeddings` | 文档切片及按模型保存的向量 |
| 讨论 | `classroom_conversations`、`conversation_messages` | 课堂话题和可见消息 |
| 讨论 | `orchestration_runs`、`agent_turns` | 一次多 Agent 编排及其角色回合 |
| 讨论 | `context_compactions`、`shared_context_memories` | 历史摘要和共享记忆 |
| 讨论 | `conversation_events`、`agent_trace_spans` | 可续传事件与链路追踪步骤 |
| 配置 | `mcp_servers`、`llm_providers` | 外部工具服务与聊天模型配置 |
| 配置 | `rerank_settings`、`vlm_settings` | 检索重排与视觉模型配置 |

`internal/model/entity/` 中的查询条件、联表视图和解析产物结构体不一定建表；是否持久化以 `AutoMigrate` 清单为准。

## 4. 核心表设计

### 4.1 课堂与页面

| 表 | 关键字段与约束 | 业务含义 |
| --- | --- | --- |
| `classrooms` | `owner_id`、`folder_id`、`requirement`、`mode`、`status` | 一门课的归属、原始目标和整体生成状态；删除文件夹时 `folder_id` 置空 |
| `classrooms` | `plan`、`plan_version`、`generation_run_id`、`generation_config`、`agent_config` | 已落库大纲及本轮执行快照；计划版本用于识别页面结果所属版本 |
| `scenes` | `classroom_id` + `sort_order` 唯一；`type`、`title`、`brief`、`status`、`phase` | 一页课件及其在课程中的顺序；`phase` 记录页内进度 |
| `scenes` | `content`、`interactive_html`、`review`、`error_message` | 结构化页面、交互内容、审核结论与失败摘要 |
| `scenes` | `run_id`、`attempt`、`lease_owner`、`lease_expires_at`、`generation_checkpoint` | 页级执行归属、租约、尝试次数及断点数据 |
| `scene_segments` | `scene_id` + `sort_order` 唯一；`scene_id` + `content_key` 唯一 | 一页中的讲解段落，`content_key` 对应页面内容块 |
| `scene_segments` | `text`、`audio_path`、`status`、`error_message` | 讲稿、可选音频路径和段落状态 |

`classrooms.status` 为 `generating`、`playable`、`ready` 或 `failed`。`playable` 表示首页已可进入；是否仍在后台生成，要结合 `generation_error` 判断。`scenes.status` 为 `pending`、`generating`、`ready` 或 `failed`。单页失败记录在该页，其他页面可继续执行；完成页面的 checkpoint 会清空。

页面租约过期后可由其他执行者接管。写入时核对执行者与租约代次，避免旧执行者的迟到结果覆盖新结果。`attempt` 用于识别本页的执行轮次，`generation_checkpoint` 用于保留页内已完成的阶段。具体更新条件见页面仓储代码，不能仅凭字段存在就绕过条件更新。

### 4.2 知识库

| 表 | 关键字段与约束 | 业务含义 |
| --- | --- | --- |
| `knowledge_documents` | `owner_id`、`kind`、`title`、`content`、`status`、`enabled` | 文档资产；`kind` 区分知识库文档与课程材料 |
| `knowledge_documents` | `content_checksum`、`ingest_stage`、`ingest_attempt`、`metadata` | 判断是否重切片、收录从哪一步恢复及防止旧 Worker 迟到写入 |
| `knowledge_upload_records` | `owner_id`、`document_id`、`original_name`、`size_bytes`、`status`、`error_message` | 一次上传的历史；文档删除后 `document_id` 置空，记录保留 |
| `knowledge_chunks` | `document_id` + `chunk_index` 唯一；`content`、`section_path` | 文档的有序切片及章节信息 |
| `knowledge_embeddings` | `chunk_id` + `model_id` 唯一；`embedding`、`dimensions` | 一个切片在某个向量模型下的 pgvector 向量 |
| `embedding_models` | `owner_id`、`name`、`dimensions`、`is_default` | 稳定的模型身份；用户内最多一个默认模型 |
| `embedding_settings` | `base_url`、`model`、`api_key_encrypted`、`is_active` | 向量服务的连接配置，与模型身份分开 |

删除文档时，其切片与向量沿外键级联删除。切换默认向量模型后，旧向量仍归属于旧模型，需要重新向量化才能由新模型召回。向量维度必须与配置及实际向量长度一致。文档收录的 `pending`、`processing`、`ready`、`failed` 状态和 `parse`、`chunk`、`embed` 阶段用于恢复和排障。

### 4.3 讨论与配置

`classroom_conversations` 归属于课程，`conversation_messages` 按 `(conversation_id, sequence_no)` 保证会话内顺序。一次用户消息可触发 `orchestration_runs`，其 `trace_id` 唯一；`agent_turns` 按 `(run_id, turn_no)` 记录角色执行回合。`conversation_events` 也按会话序号排序，用于断线续传；`context_compactions` 和 `shared_context_memories` 保存长对话所需的摘要与记忆。

`llm_providers` 按用户保存 OpenAI 兼容模型的地址、模型列表、测试和启停状态，`mcp_servers` 保存外部工具连接配置。`embedding_settings`、`rerank_settings`、`vlm_settings` 分别管理不同模型能力，不能把它们当成聊天模型配置。具体接入步骤见 [模型接入指南](model_integration_guide.md)。

## 5. 约束、索引与迁移

- 主外键、`CHECK`、唯一约束及普通索引主要声明在实体的 `gorm` tag 中，由启动时的 `AutoMigrate` 创建和对账。修改状态枚举或唯一规则时，应同时核对应用逻辑与数据库约束。
- 向量检索依赖 `pgvector`。按模型分片的 HNSW 索引由仓储代码按需维护；词法检索的表达式索引优先使用 `pg_bigm`，否则尝试 `pg_trgm`。缺少词法扩展时检索仍可运行，但大数据量下可能变慢。
- `AutoMigrate` 适合新库建表及兼容性结构演进，不能替代需要回填、清理或改变归属的存量库脚本。已有无 `owner_id` 的课堂库必须先执行 [`migrations/0012_private_ownership.sql`](../migrations/0012_private_ownership.sql)，再启动新版服务；详细步骤见 [迁移说明](../migrations/0012_private_ownership.md)。
- 其他历史数据修复及种子脚本见 [`migrations/README.md`](../migrations/README.md)。执行存量迁移前先备份数据库，按脚本说明确认适用版本。
