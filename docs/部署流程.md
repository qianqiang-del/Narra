# 部署流程

本文档描述 Narra 当前代码可执行的单机部署流程。参考项目使用的 GitHub Actions、GHCR 镜像和 Docker Compose 不属于本仓库现有交付物；这里以 PostgreSQL、Redis、一个 Go 进程和前端静态文件为准。开发期快速启动见 [README](../README.md)。

## 1. 部署组成

| 组件 | 作用 | 要求 |
| --- | --- | --- |
| PostgreSQL + pgvector | 账号、课程、页面、知识库及讨论数据 | 数据库可连接，启动账号有建扩展和建表权限 |
| Redis | Asynq 任务队列、验证码和刷新令牌 | 后端启动前可连接 |
| Narra 后端 | Gin API、异步任务消费与周期对账 | Go 1.25+ 构建，进程持续运行 |
| 前端静态服务 | 提供 `frontend/dist`，反向代理后端接口 | Node.js 20.19+ 或 22.12+ 构建；运行时只需静态服务器 |

OpenAI 兼容大模型是生成课堂的业务前置条件。Embedding、重排（Rerank）、视觉模型（VLM）、TTS、文档解析、MCP、Langfuse 和 OSS 按需求配置：三者都可以在 `config.yaml` 里配一份只读的"平台默认"（密钥分别由 `EMBEDDING_API_KEY` / `RERANK_API_KEY` / `VLM_API_KEY` 注入），用户没在设置页配自己的服务时自动回退；不配平台默认也不影响启动，只是这些能力对未配置的用户关闭。短信未启用时不能注册或使用验证码登录，已有账号仍可使用密码登录。

## 2. 首次部署

### 2.1 准备数据服务

创建 `narra` 数据库，确保 PostgreSQL 已安装 pgvector，并启动 Redis。后端启动时执行 `CREATE EXTENSION IF NOT EXISTS vector`，随后执行 GORM `AutoMigrate`。没有建扩展或建表权限会导致启动失败。词法索引优先使用 `pg_bigm`，否则尝试 `pg_trgm`；两者均不可用时仍可检索，但大数据量下性能可能下降。

**只有空库走本节的建库流程。** 已有旧库升级时先按第 5 节执行存量迁移。

### 2.2 配置环境

在仓库根目录准备本地配置。以下命令适用于 Linux/macOS；Windows PowerShell 将 `cp` 换成 `Copy-Item`：

```bash
cp configs/config.example.yaml configs/config.yaml
cp .env.example .env
```

在 `.env` 中填写 `POSTGRES_*`、`REDIS_*`、`JWT_SECRET` 等变量；在 `configs/config.yaml` 设置应用端口、存储目录和要启用的能力。生产环境可由进程管理器注入环境变量，避免把 `.env` 放入发布目录。真实密钥不要写进代码库。`JWT_SECRET` 同时用于签发 JWT 和解密已保存的模型密钥，后续更换会使原有密文无法解密。

建议将 `APP_MODE` 设为 `release`，并确认 PostgreSQL 的 `sslmode` 符合数据库连接要求。示例文件中模型、短信、语音和文档解析默认关闭。需要生成课堂时，可在登录后的设置页添加并测试用户模型，或启用 `default_llm` 并注入 `NARRA_DEFAULT_LLM_API_KEY`；详情见 [模型接入指南](model_integration_guide.md)。

`storage.upload_dir`、`storage.audio_dir`、`storage.knowledge_dir` 默认在 `data/` 下。使用相对路径时，启动进程的工作目录应保持为仓库根目录；发布到其他目录时应改为稳定的绝对路径，并赋予后端进程读写权限。OSS 的 endpoint、bucket 和两个凭证必须全部配置才会启用；全部留空则使用本地存储，配置一部分会在启动时出错。

### 2.3 构建并启动后端

在仓库根目录运行：

```bash
go build -o bin/narra-api ./cmd/server
./bin/narra-api -c configs/config.yaml
```

Windows 可执行文件为 `bin/narra-api.exe`。也可在开发环境使用 `go run ./cmd/server -c configs/config.yaml`。当前后端进程同时运行 HTTP 服务、Asynq 消费端和生成任务对账，不需要再启动一份独立 Worker；启动时 Redis 不可用会使生成任务队列初始化失败。

服务默认监听 8080 端口。检查：

```bash
curl http://localhost:8080/api/v1/health
```

预期返回 JSON，包含 `status: "ok"`。这个接口只证明 HTTP 服务已经响应；课堂生成还需配置可用模型，并用实际任务验证 PostgreSQL、Redis 和上游服务。

### 2.4 构建并提供前端

```bash
cd frontend
npm ci
npm run build
```

构建结果位于 `frontend/dist`。使用静态服务器提供该目录，同时将 `/api/`、`/audio/` 和 `/knowledge/images/` 转发到后端。前端 API 路径固定为同源 `/api/v1`；若前后端分域部署，还需匹配跨域配置与媒体地址。单页应用路由应回退到 `index.html`。以下是 Nginx 配置示意，`root` 改为实际绝对路径：

```nginx
server {
    listen 80;
    server_name _;
    root /absolute/path/to/Narra/frontend/dist;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_buffering off;
        proxy_read_timeout 1h;
    }

    location /audio/ {
        proxy_pass http://127.0.0.1:8080;
    }

    location /knowledge/images/ {
        proxy_pass http://127.0.0.1:8080;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

`/api/` 包含 SSE 长连接，反向代理不能缓存响应或过早断开；大文件上传还要按实际文件上限配置代理请求体大小与读超时。对外服务时应在反向代理层配置 TLS。后端只提供 API 和本地媒体静态路由，不会自动提供 `frontend/dist`。

## 3. 上线验证

1. 访问前端，确认静态资源正常加载；刷新一个非首页路由，确认单页路由回退可用。
2. 请求 `/api/v1/health`，确认前端域名下的 API 代理可用。
3. 使用现有账号密码登录；若启用短信，再验证注册和验证码登录。
4. 在设置页测试并启用模型，创建一门短课；确认大纲、页面生成状态和已完成页面能正常查看。
5. 若启用语音或知识库，确认 `/audio/`、`/knowledge/images/` 或对应 OSS 地址可访问。

日志可通过进程管理器输出查看；若设置了日志文件路径，还需确认其目录可写。Langfuse 只有显式启用并配置密钥后才会上报链路。

## 4. 备份与恢复

升级前备份 PostgreSQL，并保存本地持久目录 `data/` 或所配置的绝对路径。使用 OSS 时保留对象存储数据及对应配置。Redis 中有队列任务、验证码和刷新令牌；丢失 Redis 会使用户需要重新登录，排队任务也可能丢失。数据库中的课堂与页面状态供启动后的对账恢复使用，但仍应在变更前保留一致的备份。

回滚程序版本前，先检查本次是否有数据库结构或数据迁移。`AutoMigrate` 不能自动撤销新增列或恢复已改写数据；需要使用升级前备份或明确的回退脚本。不要只替换二进制就假定旧版本能读新库。

## 5. 旧库升级

已有数据库不要直接按空库步骤启动新版。先停止 API 与后台任务，备份 PostgreSQL，阅读 [迁移总说明](../migrations/README.md)。若旧库尚无用户归属字段，必须先按 [私有数据归属迁移说明](../migrations/0012_private_ownership.md) 执行 `0012_private_ownership.sql`，再启动新版服务；缺少该字段时启动代码会明确拒绝继续迁移。其他历史数据修复脚本按迁移说明和实际库版本选择执行。

迁移完成后再启动后端、验证登录与现有课程归属，并抽查课堂播放和知识库数据。生产变更应先在备份副本上演练；旧库迁移涉及所有者回填，手机号与密码哈希必须使用实际受控账号的值。

## 6. 常见故障

| 现象 | 检查项 |
| --- | --- |
| 启动时创建 `vector` 扩展失败 | PostgreSQL 是否安装 pgvector、连接账号是否有建扩展权限 |
| 启动时提示缺少 `owner_id` | 旧库未完成 `0012_private_ownership.sql`，按迁移说明处理 |
| 后端无法连接 Redis | `REDIS_HOST`、端口、密码及网络；任务队列依赖 Redis |
| 前端页面正常但接口失败 | `/api/` 代理目标与后端端口是否一致，浏览器网络请求返回什么内容 |
| 页面刷新后 404 | 静态服务器是否将非文件路径回退到 `index.html` |
| SSE 进度中断 | 代理缓存、读超时与连接保持设置 |
| 音频或知识库图片无法显示 | 媒体路径代理、本地目录权限或 OSS 地址与权限 |
| 模型不可选或生成失败 | 模型是否测试并启用；兼容地址、密钥和模型 ID 是否正确 |
