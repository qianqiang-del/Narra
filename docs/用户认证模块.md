# 用户认证模块

Narra 使用手机号注册和登录。注册、验证码登录依赖短信服务；已注册用户可直接使用密码登录。认证采用短期 JWT 访问令牌与 Redis 中的刷新令牌，业务数据按用户归属隔离。本文描述当前代码的实际行为，不包含邮箱登录、密码重置或管理员角色功能。

## 1. 接口一览

接口前缀为 `/api/v1/auth`。除 `/me` 外，下列接口本身不要求 `Authorization` 请求头。

| 功能 | 方法与路径 | 请求字段 | 主要结果 |
| --- | --- | --- | --- |
| 发送验证码 | `POST /codes` | `phone`、`purpose` | `sent: true` |
| 注册 | `POST /register` | `phone`、`password`、`code` | 用户与双令牌 |
| 密码登录 | `POST /login/password` | `phone`、`password` | 用户与双令牌 |
| 验证码登录 | `POST /login/code` | `phone`、`code` | 用户与双令牌 |
| 刷新令牌 | `POST /refresh` | `refresh_token` | 新的用户与双令牌 |
| 登出 | `POST /logout` | `refresh_token` | `revoked: true` |
| 当前用户 | `GET /me` | Bearer 访问令牌 | `id`、`phone` |

`purpose` 只接受 `register` 或 `login`。手机号接受中国大陆 11 位号码或 `+86` 前缀，服务端统一保存为 `+86` 格式；密码在当前实现中按 UTF-8 字节长度校验，要求 8 到 72 字节，验证码为 6 位数字。发送注册验证码前检查手机号未注册；发送登录验证码前检查账号已存在。

注册与登录成功返回统一数据结构：

```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "token": "<JWT 访问令牌>",
    "expires_in": 900,
    "refresh_token": "<随机刷新令牌>",
    "refresh_expires_in": 604800,
    "user": { "id": 1, "phone": "+8613800000000" }
  }
}
```

示例中的过期秒数对应默认配置，可通过 `jwt.access_ttl` 和 `jwt.refresh_ttl` 调整。Narra 的访问令牌字段名是 `token`，不是 `access_token`。普通业务错误也以 HTTP 200 返回统一响应体；调用方应检查 `code`，不能只检查 HTTP 状态。

## 2. 注册与登录

```text
注册：发送 register 验证码 → 校验验证码 → bcrypt 哈希密码 → 创建用户 → 签发双令牌
密码登录：查找手机号 → 校验 bcrypt 密码 → 签发双令牌
验证码登录：发送 login 验证码 → 校验并消费验证码 → 签发双令牌
```

`users.phone` 有唯一约束；数据库仅保存 `password_hash`，不保存明文密码。注册成功后记录 `phone_verified_at`。密码登录失败统一返回“手机号或密码错误”，避免凭响应区分账号与密码是否存在。

验证码由 Redis 保存，不写入用户表。发送冷却为 60 秒，有效期为 5 分钟；同一手机号每天最多发送 10 次、同一 IP 每小时最多 20 次。验证成功即消费；错误尝试达到 5 次后删除该验证码。普通短信通道由服务端生成验证码并保存 HMAC 摘要；使用阿里云号码认证短信通道时，验证码由服务商生成、验证，再在 Redis 中消费本次发送记录。短信未启用或不可用时，发送和验证码登录、注册无法完成；已有账号仍可使用密码登录。

## 3. 双令牌与登出

| 凭证 | 默认有效期 | 存储与用途 |
| --- | --- | --- |
| 访问令牌 | 15 分钟 | HS256 签名的 JWT；通过 `Authorization: Bearer <token>` 访问受保护接口 |
| 刷新令牌 | 7 天 | 32 字节随机值；客户端持有原文，Redis 仅以 SHA-256 摘要作键保存所属用户与 TTL |

认证中间件校验访问令牌的签名算法、签发者 `narra`、有效期和用户 ID，然后将用户 ID 放入请求上下文。后续服务及仓储读取私有资源时，还必须核对该资源的 `owner_id`，仅通过 JWT 验证不等于获得其他用户的数据访问权。

访问令牌过期后，客户端将刷新令牌提交给 `/refresh`。Redis 脚本原子地写入新令牌、删除旧令牌；刷新成功后必须同时替换本地的访问令牌和刷新令牌。旧刷新令牌无法再次使用。前端对并发请求共用一次刷新过程，请求收到 `code: 401` 时会尝试刷新并重发一次；刷新失败后清除登录状态并跳转登录页。

`/logout` 根据请求体中的刷新令牌删除 Redis 记录，前端同时清除本地登录状态。**当前实现没有访问令牌黑名单**：已签发的 JWT 在自然过期前仍可通过签名验证，登出不会使它立即失效。需要立即撤销访问令牌时，须另行设计服务端撤销机制。

## 4. 调用示例

以下请求体均为 JSON。示例中的手机号和令牌仅作格式说明。

```http
POST /api/v1/auth/codes
Content-Type: application/json

{"phone":"13800000000","purpose":"register"}
```

```http
POST /api/v1/auth/register
Content-Type: application/json

{"phone":"13800000000","password":"example-password","code":"123456"}
```

```http
POST /api/v1/auth/login/password
Content-Type: application/json

{"phone":"13800000000","password":"example-password"}
```

```http
POST /api/v1/auth/refresh
Content-Type: application/json

{"refresh_token":"<当前刷新令牌>"}
```

```http
GET /api/v1/auth/me
Authorization: Bearer <访问令牌>
```

## 5. 配置与排查

在 `configs/config.yaml` 中设置 JWT 时长，密钥通过本地 `.env` 中的 `JWT_SECRET` 注入：

```yaml
jwt:
  access_ttl: 15m
  refresh_ttl: 168h
sms:
  enabled: false
```

注册或验证码登录需要启用短信服务，并按实际选用的阿里云短信接口配置签名、模板、地域与访问密钥；具体配置字段见 [`pkg/config/config.go`](../pkg/config/config.go) 和 [`pkg/sms/`](../pkg/sms/)。Redis 不可用会影响验证码、刷新与登出。`JWT_SECRET` 同时用于项目中已保存 API Key 的加解密，部署后不可随意更换。

| 现象 | 检查项 |
| --- | --- |
| 验证码发送失败 | `sms.enabled`、服务商参数、阿里云权限和 Redis 连接 |
| “发送过于频繁” | 60 秒冷却、手机号日限额或 IP 小时限额 |
| 验证码无效 | 用途是否与发送时相同、是否超过 5 分钟、是否已消费或错误次数过多 |
| 受保护接口返回 `code: 401` | Bearer 格式、JWT 有效期及 `JWT_SECRET` 是否一致 |
| 刷新失败 | 刷新令牌是否过期、被登出撤销或已被另一请求轮换 |
| 资源不可见 | 当前用户是否为资源所有者；不能只依据有效 JWT 判断访问权限 |
