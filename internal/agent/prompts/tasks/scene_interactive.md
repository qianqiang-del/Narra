# 任务

为一页交互型课件生成一份**完整、自包含、可运行的 HTML 文档**。输入是分层上下文：课堂定位、课程页目录、**本页计划**、前后页摘要，以及可能为空的一份参考资料。

`## 参考资料`一节是这一页专门查回来的事实与出处。有资料时**以它为准**：里面的数字、版本、名称照抄，资料没提到的事实不要补。标着"本次没有可用的外部资料"时，按已有知识写，**不要编造具体数字与版本号**。

`## 审核意见`一节是上一轮审核提出的问题，**必须逐条落实**；`## 上一次生成的交互页面校验失败`说明上一轮为什么没通过，重写时要避开同样的错。

# 输出

只输出一份 HTML 文档，从 `<!doctype html>` 开始、到 `</html>` 结束。不要输出解释文字，不要使用 Markdown 代码围栏。

# 规则

## 文档结构

- 整份输出里只能有一份文档，必须有 `<!doctype html>`、`html`、`head` 和 `body`。
- 样式与脚本全部内联，写在 `head` 或 `body` 里。
- 文档大小不超过 256 KB。
- 页面按 1280 × 720 的固定逻辑画布设计，横向铺满、**整页不出现滚动条**（画布内部某个区域自己滚动是允许的，见「画布预算与溢出兜底」）。
- 页面必须能直接渲染出初始状态，不能要求用户先刷新。

## 画布预算与溢出兜底

画布高度是死的 720 像素，内容是多是少不由画布决定，所以**先把纵向额度算出来，再决定放什么**。

- 内容区纵向只有 674 像素（720 减去上下各 23 像素内边距）。正文额度 = 674 − 页头 − 页脚 − 各块之间的间距。分栏排布时，**每一栏都各自受这个额度约束**。
- **容器一律用 `min-height`，不要用固定 `height` 硬挤**。定高只用在内容恒定的地方（页头、页脚、单行状态条）；凡是内容会随数据或文案变长的盒子，都不要定高。
- **内容可能变长的区域自己滚**：表格、代码块、日志、消息列表这类区域给定高度并配上 `overflow:auto`，让它在自己的框里滚。**整页不许出现滚动条，局部滚动是允许的。**
- **外面的大面板收溢出**：用 `grid` 或 `flex` 排出来的栏位加 `overflow:hidden`，防止子元素把父容器撑破、盖到页脚上。
- **页脚是最容易被盖住的一块**：排完正文之后要留出页脚自身需要的高度（间距 + 内边距 + 一行文字），不要让它压线。

下面这份写法合格，可以直接参照（页头 83 + 主区 551 + 页脚 36 = 670，与 674 的额度正好卡满）：

```css
main{height:551px; display:grid; grid-template-columns:610px 588px; gap:18px}
.panel{overflow:hidden}           /* 栏位收住溢出，不让子元素外溢 */
pre{height:371px; overflow:auto}  /* 代码区自己滚 */
.tablewrap{height:123px; overflow:auto}
.log{height:122px; overflow:auto}
footer{height:36px}
```

反例（**不要这么写**）：把整栏写成一个固定 `height` 的卡片，卡片自己没有 `overflow`，里面再放一个固定高度的代码区。内容一多就直接溢出、盖住页脚，被裁掉的部分再也够不回来。

## 自包含

- 页面里**不允许出现任何 `http://` 或 `https://` 地址**，也不要写 `//` 开头的协议相对地址。
- 不使用外部 CDN、外部样式、网络字体、未受控图片。
- 需要图形就用内联 SVG 或 `canvas` 自己画，需要图标就用字符或 SVG 路径。
- 需要引用资料出处时，把来源名称写成纯文本，不要写成链接。

## 安全

- 不访问父页面：不出现 `window.parent`、`parent.document`、`top.document`。
- 不使用 `eval` 和 `new Function`。
- 不发起网络请求：不出现 `fetch`、`XMLHttpRequest`、`WebSocket`、`EventSource`。
- 不访问 `document.cookie`，不使用 `localStorage` 与 `sessionStorage`。
- 不自动打开窗口、不自动下载、不用 `location` 跳转。
- 页面上不要放 `form`，需要提交动作时用 `button` 加脚本处理。

## 交互质量

- 页面必须有真实的交互行为，不能只是静态说明文字加一张卡片。
- **演示用的命令链要完整**：这个知识点要靠多条命令配合才说得明白时（建组 → 读取 → 确认这类），页面上必须按顺序把整条链列全，不能只挑其中一两步。
- **写出来的每条命令都要有结果**：给出命令原文，也给出它执行后产生的东西（返回值、列表、计数、状态），不要用「显示摘要」「观察结果」这类概括替代。
- **每个可操作元素都要有能核对的结果**：学员点了按钮、改了输入之后，页面上必须出现可对照的变化（消息列表、归属关系、计数、状态），不能只提示一句「观察一下」。
- **全页共用同一份数据**：命令示例、交互控件、结果展示里出现的流名、组名、消息 ID、字段值必须是同一套，不要一处一个名字。
- **给学员抄的代码只有两种合格形态，必须选一种并写明**：要么是**完整自包含的全文**——每个用到的变量、句柄、上下文都在这一段里声明过，从这一段开始就能直接编译运行；要么是**只留占位符的骨架**——占位处用 `____` 标出，填法在同一页给出。不要写成「上面声明过、下面直接用」，也不要写成「下面又声明一遍」的混血形态。
- **核对答案要与页面骨架对得上**：页面已经展示过 `ctx`、`rdb`、客户端句柄这类声明，答案里就不要再写一遍；答案里出现的每个名字，都要能在答案本身或页面骨架里找到出处。答案里带循环、错误分支时（跳过 `redis.Nil`、只对成功的消息确认），把整个循环结构写全，不要用一句注释代替。
- 至少有一个可操作元素：`button`、`input`、`textarea` 或 `canvas`。
- **不要用原生 `<select>`**：它展开后的列表是浏览器自己画的——页面的样式管不到它，容器的 `overflow:hidden` 也关不住它，会盖住旁边的卡片、甚至跑到面板外面，换一个操作系统还换一副长相。需要「多选一」时用一排按钮做成分段控件（`button` 配 `aria-pressed`，选中态自己上色）；选项确实多到一排放不下时，用 `button` 加一份自己写的绝对定位列表，把它定位在同一个容器内，并给它固定宽度与 `z-index`。
- 必须有脚本为这些元素绑定事件（`addEventListener` 或 `on*` 属性），并在事件里真的改变页面状态、数值或图形。
- 交互元素要带稳定且唯一的 `id` 或 `data-*` 属性，供后续标注与高亮使用。
- 支持鼠标操作，同时兼顾键盘可访问性：`button` 与表单控件要能被 Tab 聚焦、能回车或空格触发。
- 初始状态、操作过程和结果反馈要一眼看得懂：给出数值、单位、图例或文字结论。
- 只把课堂文字放进一张静态卡片不算交互页面。

# 交付前自查

交卷前把下面三条过一遍，任何一条不过就先改好再输出：

1. **画布**：把每一栏的固定高度与间距加总，是否 ≤ 正文额度（674 减去页头、页脚与块间距）。加总超了就是已经溢出，要么删内容，要么把那一块改成 `min-height` 加 `overflow:auto`。
2. **示例代码**：把页面里每一段代码单独拿出来，它能不能从自己开始跑通；不能就补全，或者明确标成占位符骨架。
3. **一致性**：命令示例、交互控件、结果展示里的流名、组名、消息 ID、字段值是不是同一套；每个可操作元素操作之后，页面上有没有出现可对照的结果。
